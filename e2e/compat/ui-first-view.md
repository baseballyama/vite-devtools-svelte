# UI first-view checklist (compat samples)

What a person checks when opening `/.svelte-devtools/` for the first time on `plain-svelte` (plain Svelte + Vite, `examples/plain-svelte`) and
`kit3` (SvelteKit 3, `e2e/compat/kit3`). Run it only in a granted slot. Record each item as PASS, FAIL or NOT RUN, together with the
profile and the plugin tarball version. "Not applicable" items must show an honest empty state, not an error.

Both apps run a bounded ticker (1 s, at most 120 ticks), so there is activity without input. Start checking within
2 minutes of loading the app page.

| #   | Panel                                                                     | What to check                                                                                                                                                                                           | plain-svelte          | kit3    |
| --- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------- | ------- |
| 1   | Auth gate                                                                 | Asks for the one-time code printed by the dev server; the code (or the printed link) lets you in; no code or token appears in the URL after login                                                       | yes                   | yes     |
| 2   | Header                                                                    | Status reads Connected; no console errors in the DevTools tab                                                                                                                                           | yes                   | yes     |
| 3   | Overview                                                                  | Project name and versions match the profile in `matrix.json` (Svelte, Vite, Kit, or no Kit)                                                                                                             | Kit row absent or "—" | Kit 3.x |
| 4   | Components                                                                | Tree shows `App` > `Counter`, `TodoList` (plain-svelte) or the page > `ProductList` (kit3); selecting a node opens the inspector; no "Showing N of M" notice (small app)                                | yes                   | yes     |
| 5   | Components → Show reactivity                                              | Opens Reactivity scoped to that instance; the scope bar shows `<Name> #id`                                                                                                                              | yes                   | yes     |
| 6   | Reactivity: Overview                                                      | Record strip shows the window, "sampled every 200 ms", coverage and "N active of M registered" (no "unknown" for M); `App` or the page is listed with "≥ N" changes growing with the ticker; no "Stale" | yes                   | yes     |
| 7   | Reactivity: Component                                                     | `ticks` ($state) and the derived values appear. Edges are labelled "can affect"; the Cause row says "Not recorded"; "Go to definition (by name)" opens the right file                                   | yes                   | yes     |
| 8   | State timeline                                                            | `ticks` changes appear newest first with old → new; the toolbar shows "sampled every 200 ms · latest 500"; typing in the input (draft / query) adds entries                                             | yes                   | yes     |
| 9   | Render                                                                    | `App`/page and child components have render counts; clicking a button increases the child's count                                                                                                       | yes                   | yes     |
| 10  | Routes                                                                    | plain-svelte: honest empty state (no `src/routes`). kit3: one route `/` marked page with a server load                                                                                                  | empty                 | 1 route |
| 11  | Load functions                                                            | kit3: one server `load` for `/` after a full page reload. plain-svelte: empty state                                                                                                                     | empty                 | yes     |
| 12  | Compiled output                                                           | Pick `Counter.svelte` / `ProductList.svelte`; source and compiled JS side by side                                                                                                                       | yes                   | yes     |
| 13  | HMR                                                                       | Edit the text in a child component; the Components tree keeps the selection and Reactivity re-reads without errors                                                                                      | yes                   | yes     |
| 14  | Dev-server restart                                                        | Restart; the page reconnects (or asks for a code again only if the token was lost); the Overview shows "counts restart" behaviour, not stale numbers                                                    | yes                   | yes     |
| 15  | Dock (`dock` mode: `SDT_MODE=dock` on plain-svelte, `DevTools()` on kit3) | The Svelte entry appears in the Vite DevTools dock and opens the same panels; sign-in is handled by Vite DevTools                                                                                       | yes                   | yes     |

**Not claimed by this checklist:** performance, large apps, and value inspection, signal history or update cause
(these show "not available yet" / "Not recorded" by design).
